# Gallery 图片发布

[通用油猴脚本](gallery-publish.user.js)，适用于桌面 Tampermonkey 5+。页面图片悬停后右上角出现“发布”，点击打开预览和分类面板；确认发布后，任务在当前来源页面后台排队执行取图、上传、投稿和审核，并以系统通知告知结果。没有网页图片的“已投稿”标记，也不扫描 Gallery 的历史记录。

## 安装和使用

1. 在油猴中新建脚本，粘贴完整脚本并保存。更新时覆盖同名脚本，不与旧版同时启用。
2. 在油猴菜单选择“Gallery 发布设置”，保存 Gallery 开发者令牌。个人安装版已预填初始令牌；之后修改、清除都使用油猴存储。
3. 令牌选择“月离图库” (`gallery-main-web`)，需要 `media.upload`、`gallery.submission.create`、`gallery.submission.read_own`、`gallery.submission.review`。账号本身也须有审核资格。
4. 把鼠标移到图片上，点“发布”。确认预览、标题、分类、标签及来源页面，再点弹窗底部“发布”；任务加入后台队列后弹窗自动关闭，可以继续浏览或选择下一张；成功时点击系统通知打开对应图片。
5. 勾选“记住本次分类”后，下一张图片沿用分类和 Facet 选择；每次仍从 Gallery 读取可用分类及约束。

## 后台任务与通知（1.4.0）

确认“发布”后，弹窗自动关闭，右下角显示“发布任务”。每张图单独保存当时的标题、分类、标签、来源和令牌；同一页面的任务依次执行，后续打开或关闭弹窗、编辑下一张图片不会改变已有任务。勾选“记住本次分类”时，在任务入队后立即记住，下一张可直接沿用。任务不自动弹出面板或抢占窗口焦点。

成功或重复图片结果会发送系统通知，点击打开该图片的 8 位地址。失败通知会显示原因，点击可在来源页查看任务；也可点右下角按钮或油猴菜单“Gallery 发布任务”。任务面板保留技术详情、我的投稿链接及可用的“重试／继续发布”。审核权限不足时可在任务中打开令牌设置，保存后手动继续；复用已经上传的资源和同一投稿。失败任务不阻止其他排队任务。

上传、保存或创建投稿的写入结果不确定且没有投稿 ID 时，不提供盲目重试，也阻止同一图片新建另一个任务，先到 Gallery 核对。有投稿 ID 的审核结果不确定时，手动继续会先读取该投稿状态，已发布则直接完成。进行中的任务固定使用入队时的令牌；更改设置作用于新任务和手动继续的任务，不在一次任务内部切换账号授权。

这是当前网页文档内的后台队列。可以滚动页面、切换标签，网站不重载文档的页面切换也会保留任务；刷新、整页跳转、关闭来源标签或浏览器丢弃该页都会中断，队列不会保存或自动恢复。仍有运行/排队任务时会使用浏览器的离开页面提示。已创建的投稿保留在 Gallery，未完成的上传沿用 Asset 草稿生命周期。

更新脚本需要新增 `GM_notification` 授权，并允许油猴/浏览器在系统中显示通知；系统静音或禁用通知时可能看不到提醒。脚本不改用网页 Notification、alert 或其他渠道。若通知 API 明确报错，任务中显示“系统通知未能发送”，不会把成功发布改为失败。点击图片通知由 [Tampermonkey 的 url 属性](https://www.tampermonkey.net/documentation.php?locale=ja&q=GM_notification) 处理，故以桌面 Tampermonkey 5+ 为支持范围。

## 新增分类、作品和角色（1.1.0）

“分类”和每个现有维度标题右侧提供“＋ 新增”。例如在“作品”旁新增作品、在“角色”旁新增角色；不是创建新的维度类型。标签继续使用原有自由输入和服务端标签提案流程。

输入名称后自动生成可编辑的链接标识；点“保存并选中”会将项目加入 Gallery 的全站目录并选中，不只是保存在脚本本地。此功能额外需要 `gallery.classification.read` 和 `gallery.classification.govern`，账号也须有相应治理权限。

新增遵循正式三步合同：读取分类目录检查同范围名称/标识；`POST /api/v1/gallery/admin/classification/identities` 创建草稿；对该 ID 以 `set_status → active` 调用 `governance/preview`，把返回的 catalog revision / request token / impact token 原样传入 `governance/execute`。只有刷新公开投稿选项确认项目可用后，才选中新项目。保留其他已选分类、维度、标题等字段。

已启用的同名项目直接选中；标识属于其他名称时要求修改。已有未启用同名项目提示到管理目录处理，不擅自启用。当前任务刚创建的草稿若启用失败，可以“继续完成”，重新读取状态与治理计划，避免重复创建；创建结果未知时停止重发，先在管理目录核对。取消不删除已经保存的目录草稿。

1.2.0 起，作品与角色使用同一个 `work` 维度：作品／系列是根节点，角色放在其所属作品下。新增角色必须选择所属作品；没有所属作品的选“独立角色”，出处暂不明确的选“待归属角色”。作品和角色都可以单独选中，多角色图片可以多选。“游戏/动漫”等分类保持独立，联动不改变角色的主要归属。新增分类和其他维度值也可选择父级。

此版本需要先应用 Gallery 的 `0023_work_character_tree` 迁移并更新网站；检测到旧的独立 `character` 维度会停止发布并提示先更新。不要在旧站上用新版脚本新增角色。升级与数据处理见[作品与角色树](../docs/work-character-tree.md)。

1.2.1 修复浏览器 Canvas 输出 WebP 携带 ICCP 导致 Asset 保存返回 `asset.image_process.invalid_request`（HTTP 400）的问题。先在 sRGB 画布完成颜色转换，再清除输出 WebP 的 ICCP/EXIF/XMP 块并同步 RIFF 长度与 VP8X 标志，保留图像编码、尺寸和透明度；不直接移除原图的颜色配置。作品按钮紧凑排列，有角色的作品单独分组，角色缩进显示。失败原因原位显示，技术详情保留 HTTP 状态、公开错误码和追踪号，不展示服务端内部消息或凭据。

支持主页面中显示尺寸至少 80×80 的 `img` / `picture` 图片和单一 `background-image`。使用浏览器当前加载的图片 URL，不猜测网站原图地址；不处理 iframe、canvas、伪元素或多层背景。源图片支持 JPEG、PNG、WebP 静态图片，GIF/SVG 和动画 PNG/WebP 会拒绝。客户端上限 20 MiB，Asset Profile 可有更严格限制；遵循 Gallery 当前主路径，转为长边不超过 4096px、去除元数据的 WebP 后上传。

## 图片特征（1.5.0）

“图片特征”统一使用六个折叠分组：人物外观、服饰装扮、动作表情、画面构图、场景背景、表现形式。默认收起，可搜索分组或具体特征，已选项直接显示并可移除；目录标题不进入投稿。新增特征时必须选择所属分组，仍需现有分类治理权限。

选定的特征随其他元信息固定在后台发布任务中，关弹窗继续浏览、完成通知及点击打开图片的行为保持。覆盖安装沿用同一脚本身份与保存令牌。

需要网站应用 `0025_image_features` 迁移并部署配套API/Web，才会取得新目录。具体分组、组合筛选与历史图片处理见[图片特征](../docs/image-features.md)。

## 图片短地址（1.3.0）

需要与 Gallery 图片公开键迁移配套使用。发布和重复图片结果使用服务端返回的 `imagePublicId` 打开 8 位网页地址，不把内部 `imageId` 当成网页地址。旧 UUID/22 位网页地址在测试阶段停止接受；见[图片公开地址与数据迁移](../docs/image-public-keys.md)。

## 错误来源区分（1.3.1）

“读取图片”失败来自原图地址，401/403 不再提示 Gallery 令牌有问题；原图失效、限流和网络/超时分别提示，不显示“写入结果未确认”。Gallery API 的授权失败指向 Gallery 令牌/账号权限，Asset API 指向媒体授权，二进制上传地址拒绝写入单独说明。只在 Gallery/Asset API 响应中识别服务错误码与追踪号，外部网站响应不能冒充 Asset 错误。

上传流程是下载原图 → sRGB/WebP 转换 → PUT 图片 Blob → Finalize 得到 assetId → 创建投稿。投稿里的 sourceUrl 仅记录来源网页，不作为图片上传内容，也不让 Gallery 去下载源图。

## Pixiv 图片请求来源（1.3.2）

从真实 `https://www.pixiv.net/` 页面选择 `https://i.pximg.net/` 图片时，下载请求携带该页面的实际 Origin 作为 Referer（`https://www.pixiv.net/`）。来源取自选图时的页面地址，不使用可编辑的“来源页面”字段；不转发 URL 查询、Cookie 或 Gallery 令牌。图片元素或页面 meta 明确设置 no-referrer / same-origin 时不添加该头，其他页面、域名和相似域名也不添加。只有一次主下载请求，没有失败后换来源重试。

此修正匹配 Pixiv 页面允许的正常图片来源，不扩大来源网站的登录或访问授权。公开配图可匿名显示，但省略来源的另一次下载可能返回 403；这与 Gallery 令牌权限无关。浏览器已显示的跨域图片仍可能禁止 Canvas 导出，脚本保留下载原字节、格式/动画校验及 WebP 转换，不能用直接截图的方式代替这些检查。

## 请求和凭据边界

`@connect *` 用于读取用户所点图片的来源及 Asset 返回的对象存储上传地址。图片下载不带 Gallery PAT、登录 Cookie 或自定义网站凭据；Pixiv CDN 请求按上节保留真实页面来源；如仍因登录或其他访问授权被拒绝则停止，不冒用其他页面来源、不转发源站登录凭据，也不改走代理或截图。

PAT 只发送到固定 `https://gallery.yuelili.com/api/v1/*` 与 `https://asset.yuelili.com/api/v1/*`，附带 `X-Yueli-Token-Site: gallery-main-web`；这些 API 请求遇到重定向即停止。上传二进制使用 Asset 返回的请求头和地址，不附加 PAT；Asset 自有 `/api/v1/assets/blob/` 按其公共上传合同归一到 Asset 正式 HTTPS Origin，外部存储的预签名地址原样使用。脚本使用封闭 Shadow DOM 承载设置，不把令牌写入网页 Cookie、localStorage 或日志。

公开脚本不内置任何凭据。个人安装版保存在用户 `.secret/yueli/`，包含初始令牌，不分享、不提交；当前凭据来源和个人安装入口由该分类 README 维护。已有 `.secret/yueli/gallery-publishing.env` 仍是本机凭据真值；更新令牌后可重新生成个人副本，已安装脚本需在油猴设置中更新。

## 真实接口顺序

- 读取 Gallery `GET /api/v1/gallery/submission-options`，按返回的分类和 Facet 数量约束组装正文。
- 匿名下载所选图片、验证格式/动画并转换。
- Asset `POST /api/v1/asset-references/drafts` 创建临时上传草稿。
- Asset `POST /api/v1/assets/upload-init`，使用 `siteKey=gallery`、`profileKey/category=gallery-submission`、`visibility=private` 和预处理 WebP。
- PUT 二进制，再 Asset `POST /api/v1/assets/finalize`，带 `uploadToken` 与 `draftSessionId`。
- Gallery `POST /api/v1/gallery/submissions`，带正式 `assetId`、标题、说明、来源、分类、Facet 和标签。
- 每两秒从 `GET /api/v1/gallery/me/submissions?page=1&size=100` 读取当前已知投稿，最多 60 轮（通常约两分钟，后台标签节流可能延长）；按正式审核合同，`ready` 且安全状态为 `safe` 或 `uncertain` 后调用 `POST /api/v1/gallery/admin/submissions/{id}/review`，`decision=approve`。是否准许发布仍由服务端判断；处理失败、安全阻断不会发起审核。
- 只有服务端确认同一投稿 `published` 或 `duplicate` 才显示成功并提供公开图片链接。

准确合同见[开发者令牌指南](../docs/developer-tokens.md)、[开发者 API 目录](../docs/developer-api/index.md)与 Asset [对象引用和临时草稿](../../asset/docs/object-reference-lifecycle.md)。网络能力以 [Tampermonkey GM_xmlhttpRequest 文档](https://www.tampermonkey.net/documentation.php?q=GM_xmlhttpRequest)为准；脚本独立计时中止请求，避免 Chromium 的 fetch 模式忽略原生 timeout。

## 失败和继续

已保存投稿后处理较慢或审核失败，可在同一弹窗点“继续发布”，只继续当前投稿，不重新上传。审核权限不足时，可在弹窗内更换令牌再继续；仍须使用对该投稿有权限的同一账户。

上传、保存或创建投稿发生网络超时且结果未知时，停止后续写入并禁用再次发布，先到 Gallery 确认，避免重复创建。明确的 4xx 拒绝允许修正后手动重试；已确认的 Asset 不重新上传。关闭编辑弹窗不影响已入队任务；刷新或离开来源页会结束该页内存任务，未保存的上传按 Asset 草稿期限处理。不要对结果未知的写入盲目重发。
