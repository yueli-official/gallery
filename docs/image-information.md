# 图片信息维护

图片详情根据权限显示“编辑信息”或“补充信息”。编辑入口使用当前图片的内部 ID，直接进入 `/manage/images/{imageId}`；图片集合的编辑操作也进入同一页面，不再按标题搜索。公开分享链接仍使用 8 位 publicId。

普通用户和游客可在“补充信息”提出标题、说明、替代文本、来源、主分类、作品角色和图片特征的修改；图片特征沿用六组目录，分组收起并支持搜索。只提交有变化的字段，未填写的字段不会被清空。标签页沿用既有标签提案和新词审核流程。

信息建议通过现有 `POST images/{imageId}/cases` 提交，类型为 `metadata_correction`，包含 `proposedMetadata` 和图片版本 `expectedImageUpdatedAt`。网页为游客取得既有临时身份。建议进入处理单，审核前不改变公开图片；同一贡献者每分钟最多提交 10 次信息建议，超额保留草稿。

后台处理单展示具体变更。采纳调用既有处理接口并传 `applyMetadata: true`，同时要求 `gallery.case.resolve` 和 `gallery.image.update` 权限；只具处理单权限不能修改图片。图片更新和处理单结案在同一事务完成，已处理、图片版本过期或目录版本冲突均不部分写入，建议保持待处理以便重新核对。驳回不改变图片。分类修改保留当前图片标签；标签提案仍在原队列单独审核。

有编辑权限的用户在单图页面直接编辑，沿用 GET/PATCH `admin/images/{imageId}`、现有分类策略和版本冲突保护。保存失败保留草稿，离开未保存页面会确认。迁移 `0026_image_metadata_corrections` 扩展现有处理单结构，不改动已执行迁移字节。
