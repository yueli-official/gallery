# 用户补充标签

图片详情的“补充信息”中，标签页供游客和登录用户补充其他关键词。游客复用 Identity 现有临时身份和站点访客会话，无需注册或登录，不新增身份服务。分类、作品与角色使用结构化分类；发色、发型、服饰、配件、构图与场景等优先选择“图片特征”。完整信息补充及审核见[图片信息维护](image-information.md)。

输入时查询真实的 active 标签目录，包含尚未关联图片的预设词；别名也参与检索，例如“白丝”建议“白色丝袜”。初始提供 28 个词和 5 个别名。后台仍通过分类管理新增、停用和合并标签；预设只初始化一次，重启不会恢复运营人员停用或删除的词。

用户可选已有词或补充新词，一次最多 10 个，每个最多 32 个字符。所有贡献先进入现有标签提案队列；通过前不进入图片标签、推荐或公开筛选。后台可查看对应图片，通过提案、归入已有标签或拒绝。归入已有标签会登记别名。图片不再公开时不能提交或批准贡献，仍可拒绝待审项。

为避免重复排队，同一身份、同一图片、同一规范化词只保留一条提案；重复提交返回原提案，包括已处理结果。游客按临时身份在滚动 60 秒内最多新增 10 个标签，跨图片累计；并发请求也共享额度，批次超额整体拒绝，原稿保留。审核通过或拒绝不返还当前分钟额度。登录账号沿用最多 50 条待审、24 小时内最多新建 100 条的队列上限。限制针对新增提案，不阻止读取已有提案结果。

游客额度绑定临时身份，而非 IP。清理访客 Cookie 会获得新临时身份；这项限额不是 IP 级防刷。

## 接口与数据

- `GET /api/v1/gallery/tag-suggestions?q=`：返回 `{items}`，最多 28 个 active 规范词；查询匹配规范词及别名，不暴露未审核的新词。
- `POST /api/v1/gallery/images/{imageId}/tag-proposals`：用户或游客凭现有身份提交 `{tags: string[]}`，返回 `{items}`，包含提案状态；没有任何有效身份的直接 API 调用、机器身份和未声明此权限的个人开发者令牌不能提交。网页 BFF 在游客首次写入时取得临时令牌。
- 现有后台 `admin/classification/tag-proposals` 列表与 review 接口继续处理投稿及图片贡献。

迁移 `0016_image_tag_proposals` 增加图片目标、贡献者、唯一约束和预算索引。投稿目标和图片目标必须二选一，不伪造投稿记录。原投稿审核仍写投稿标签和已发布图片标签；图片贡献只写图片标签。新安装和已有站点均由 bootstrap 一次性初始化词库。

迁移 `0017_guest_tag_proposals` 增加贡献者类型，已有图片贡献标记为 user；新游客贡献标记为 guest。唯一键与事务锁同时区分身份类型，后台队列标明“游客补充”。不修改已执行的 0016 迁移。

本次只修改 Gallery；没有更改 Foundation 分类模块或其他站点合同。
