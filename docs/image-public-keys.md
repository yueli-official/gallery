# 图片公开地址

图片网页地址为 `/images/<publicId>`。`publicId` 是 Foundation `CompactURLV1` 分配的 8 位、大小写敏感 Base58 键，由 `gallery_images.public_id` 持久保存，唯一性由数据库约束和共享库的有界冲突重试保证。UUID 主键、业务外键及现有内部 API 资源 ID 保持稳定，不把 UUID 截断为公开键。

公开网页通过 `GET /api/v1/gallery/images/by-key/{key}` 查询。图片卡片和详情 DTO 返回 `publicId`；投稿、处理单、标签提案和后台评论通过 `imagePublicId` 生成公开链接。原有 `/api/v1/gallery/images/{imageId}` 是内部资源 ID 查询接口，供图片选择、收藏、评论、下载和治理等动作使用，不承担旧网页地址跳转。

网页只接受 8 位参数，服务端使用共享 Profile 严格解析。内部测试阶段不保留 UUID 或 22 位 Base64 网页地址，不建立别名表、短链重定向或旧格式兼容。

## 已有图片迁移

必须配套更新 API、Web 和发布脚本，且在旧 API 停止写入后执行：

1. 按发布合同备份数据库，记录图片数、分类/标签/专题关联及投稿数。
2. 执行新增 SQL 迁移 `0024_image_public_keys`，增加列、格式检查和唯一约束。
3. 在同一数据库运行 `gallery-imagekeys`，通过 `GALLERY_DATABASE_URL` 传入连接。源码入口是 `api/cmd/imagekeys`；运行镜像内路径是 `/usr/local/bin/gallery-imagekeys`。Compose 的 `gallery-bootstrap` 也会执行相同回填。
4. 回填命令在一个事务中锁定图片表，为缺失项分配共享短键，最后设置 NOT NULL。失败整体回滚；再次执行保留全部已分配键。它不修改图片 UUID 或关联。API 启动会检查非空约束，未完成回填时拒绝启动。
5. 核对全部图片都有唯一的 8 位键及原有数据计数，配套启动新 API/Web；验证列表、详情、相关推荐、前后导航、分享、投稿结果和后台查看入口。旧网页地址应为 404。

不要在生产重跑开发数据初始化。既有 Asset 对象引用保留实体 UUID；新引用、发布投影和后续对象同步生成短网页地址。回填后运行 `gallery-asset-references -refresh-image-urls -actor <维护操作者>`，通过共享引用事务为旧展示地址登记新版本与持久任务；等待队列应用后核对 Asset 台账已使用短地址。重复执行跳过已刷新地址，删除图片仍保留删除语义。`force` 只会重发旧持久 payload，不能完成地址投影；不要手改 payload 或队列。
